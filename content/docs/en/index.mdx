These guides are for members with workspace access and for business and technical teams evaluating an integration. Confirm your role, available environment, and permissions before choosing a work surface. Models, tools, and execution environments can differ between installations; use the configuration available in your environment.

Start with [Getting started](/docs/getting-started) if you are new to the product. For commercial evaluation, see [Pricing](/pricing): POCs and enterprise projects are assessed and quoted separately.

## Choose an entry point for your work [#choose-an-entry-point-for-your-work]

| What you want to do | Where to start | What to prepare |
| --- | --- | --- |
| Collaborate toward an ongoing goal | [Projects and SkyBot](/docs/projects) | Goal, project materials, collaborators, and acceptance criteria |
| Produce a reviewable code change | [Engineering tasks](/docs/tasks) | Requirements, repository, flow, and execution environment |
| Repeat a type of work | [Automations](/docs/automations) | Run rules, inputs, permissions, and result handling |
| Reuse employee responsibilities and methods | [Digital employees](/docs/employees) | Responsibilities, prompt, model, skills, and tools |
| Make team materials searchable | [Enterprise knowledge](/docs/knowledge) | Sources, maintainers, publication, and access scope |

## Separate completion from acceptance [#separate-completion-from-acceptance]

Work status, tool execution, automated checks, and business acceptance describe different outcomes. After reviewing the run records and artifacts, an accountable person should check that the result meets expectations. Merging code, publishing content, changing production, and broadening data access require their own authorization and follow-up actions.

The checklists in these guides help structure an evaluation. They do not mean the system performs all business acceptance automatically. Product scenarios on the website illustrate capabilities and do not create real tasks.
