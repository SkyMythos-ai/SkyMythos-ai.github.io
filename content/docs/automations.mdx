---
title: 自动化流程与运行
description: 配置重复工作的任务、环境与触发规则，逐次检查实际运行。
---

自动化将重复工作组织为可保存的流程与独立运行。流程定义描述如何工作；每次 Run 记录某次实际输入、执行与结果，两者不是同一个对象。

## 先选择一个可重复目标

第一次建议选择“根据给定反馈生成待确认摘要”等可检查工作，先手动验证，再接入定时或事件。这是 POC 方法建议，不意味着产品只有手动入口。

进入 Automations 的流程列表，选择“新建流程”。准备一个可用运行环境和适用员工或能力。自动化流程与[研发任务](/docs/tasks)中的工程 Flow 属于不同工作面，不应把两处配置当成可以直接互换。

## 配置任务与环境

编辑页可使用单 Agent 或多 Agent 模式。单 Agent 配置一个任务；多 Agent 在步骤中组织任务与依赖。第一次不必为了显示复杂度增加多个无实际职责的步骤。

| 配置 | 需要表达什么 |
| --- | --- |
| 流程名称 | 让操作者能辨认重复工作的目的 |
| 任务指令 | 处理何种输入、采用什么方法、输出什么及何时请求确认 |
| Agent / 能力 | 选择任务需要的员工与扩展能力 |
| 运行环境 | 本次执行使用的环境和需要引用的环境变量 |
| 触发方式 | 手动、定时、Webhook 或当前可用连接器事件 |
| 结果去向 | 需要发送时，从当前可用目标中选择；也可以不发送 |

多 Agent 流程有默认环境，未明确覆盖的步骤继承它。环境变量选择来自当前环境；显示缺失时应补齐正确环境或修正引用，不在指令里粘贴密钥来绕过。

指令中的参数会生成运行时输入。需要使用前一步结果时，使用页面提供的步骤结果插入入口，并检查依赖关系；不要把尚未产生的结果写成已经可用的上下文。

## 保存与试运行

编辑中的草稿和可运行快照分别管理。配置完整后使用“保存”，界面会校验任务、环境、能力及其他必要条件，服务端继续核对当前授权。

当前产品没有要求操作者再点击一个独立的“发布”按钮。完整保存后形成可运行配置；尚未形成正式运行配置的草稿可继续编辑，也可从试运行入口测试。试运行仍会校验当次草稿、必需输入、环境与授权，不意味着缺少任务或必需环境也能执行。配置已有暂停状态时，保存不会自动替你决定恢复触发。

从运行入口填写参数；有定义的输入可使用表格或 JSON 方式准备。核对输入后明确发起，再检查该次运行结果。当前试运行不发送流程结果通知，但仍可能调用工具和产生外部动作，应使用已授权的 POC 资源，不能把“试运行”当成无副作用预览。

## 再接入定时或事件

定时配置要同时核对频率、时间与时区；已有配置保留其保存的时区，不以当前电脑时区自动替换。事件触发需选择真实可用连接器、事件类型及必要过滤和参数映射。

Webhook 地址与签名信息来自已保存配置，未形成可运行配置时不会有可用地址。签名密钥仅向具备相应权限的管理员提供，不将页面截图或完整地址当成可以公开共享的资料。

保存触发规则后，仍应检查一条实际发生的 Run。规则存在、事件被接收与业务工作完成分别核对，不能据此承诺任意企业系统已接通。

## 阅读每次运行

从运行列表打开具体记录，检查实际输入、步骤、输出、等待事项与错误。等待中先处理该次运行需要的决定；失败或取消后，“重新运行”会以原输入发起新的运行，不是改写旧记录。

运行中可按可用入口请求取消，但请求受理不意味着已经发生的外部动作被撤销。暂停流程与取消某一次 Run 也不同，操作前先确认目标。

如果提交后显示结果不确定，应先核对原次运行，使用页面提供的恢复方式，不连续创建多个相同运行。费用数据还可能不完整，不能把未提供或未知金额当作零成本。

## POC 验收建议

至少保存一次输入、一次实际运行记录、对应输出与人的检查结论；需要触发规则时，再验证规则产生的 Run 与预期输入一致。对于通知、合并或生产修改，事先约定授权与人的决策方式。

需要准备依赖时，阅读[企业接入检查](/docs/private-deployment)；希望复用已确认方法时，阅读[数字员工](/docs/employees)。
