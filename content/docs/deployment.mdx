## 本指南适用的环境

以下入口面向已取得源码、镜像和安装配置访问权限的技术团队，命令从源码仓库根目录执行。本地示例使用 `minikube-ubuntu` context、`fusion` namespace 和 release；其他安装点应使用交付时确认的值。

当前源码构建采用 Node.js 24、pnpm 9.15.9，Go 声明 1.26.9、工具链为 go1.27.2。这是当前版本基线；使用其他交付版本时，以随附文档为准。镜像部署不要求在集群节点安装整套源码工具链。

## 检查集群前置条件

当前 Chart 要求 Kubernetes 1.26+、Helm 3；操作端准备 kubectl、Bash、jq 和 Python 3。以下查询是只读操作：

```bash
kubectl --context minikube-ubuntu get nodes
kubectl --context minikube-ubuntu get storageclass
kubectl --context minikube-ubuntu get crd sandboxes.agents.x-k8s.io
```

确认节点可用、存储类符合持久化要求、Agent Sandbox v0.5.4 CRD/Controller 已安装。还需要真正执行 NetworkPolicy 的网络层、匹配节点架构且可拉取的固定 digest 镜像，以及有效模型连接。对象存在本身不证明隔离或存储已通过验收。

## 准备三份安装点配置

配置保存在仓库外，并在后续升级中继续复用：

| 文件 | 内容与检查重点 |
| --- | --- |
| `helm-private.yaml` | 平台及组件技术密钥；不包含自动生成的业务模型 Key |
| `site.yaml` | 实际访问地址、真实组织 ID、Secret 引用、组件与存储选择 |
| `images.yaml` | 已发布、可拉取且固定 digest 的控制面、Runtime 等镜像 |

全新安装先按随附部署手册准备 Secret、临时启动平台并创建首位管理员和真实组织，再填回组织 ID、配置模型并完成 LightRAG 安装。临时 bootstrap 不是完整交付。已有安装不要重新生成组织、密钥或空卷。

## 预检后执行安装或升级

配置齐备后，先运行预检。它读取真实集群并执行 Helm 服务端 dry-run，不安装或升级，也不输出渲染清单；Helm 必须支持 `--dry-run=server` 和 `--hide-secret`。

```bash
deploy/helm/deploy-local.sh "$HOME/.config/fusion/helm-private.yaml" \
  -f "$HOME/.config/fusion/site.yaml" \
  -f "$HOME/.config/fusion/images.yaml" --check
```

预检通过后，去掉 `--check` 执行下面的写集群操作：

```bash
deploy/helm/deploy-local.sh "$HOME/.config/fusion/helm-private.yaml" \
  -f "$HOME/.config/fusion/site.yaml" \
  -f "$HOME/.config/fusion/images.yaml"
```

标准入口强制完整安装需要的 LightRAG，等待工作负载和初始化 Job，并检查物化器部署参数。升级前备份配置、Secret 与持久数据；旧任务和开发机不会因为 Helm 镜像值更新就自动换版。

## 访问并验证实际结果

本地可保持下面的端口转发运行，再访问 `http://localhost:8080`。它建立本地到集群服务的访问通道，不安装资源；站点 `publicURL` 应与实际浏览器来源一致。

```bash
kubectl --context minikube-ubuntu -n fusion port-forward service/fusion-http 8080:8080
```

在另一个终端执行只读健康检查：

```bash
helm --kube-context minikube-ubuntu -n fusion status fusion
kubectl --context minikube-ubuntu -n fusion get deploy,pod,svc,pvc,job
curl --fail http://localhost:8080/healthz
curl --fail http://localhost:8080/readyz
```

基础状态通过后，继续验证真实模型调用、文件持久化、Knowledge 索引与召回、含已发布 Skill 的任务和交付证据。健康接口通过不能替代业务验收。出现异常时使用[问题定位指南](/docs/troubleshooting)。

## 源码开发时的控制面入口

已配置依赖和执行环境的开发者可运行 `make run-local`：它先构建 Console，再启动宿主机 Control Plane，明确采用 Kubernetes 执行驱动。它不是免集群的一键完整安装器，也不自动准备全部生产依赖。

初次接入前，先[与团队确认 POC 环境和交付范围](/poc)。
