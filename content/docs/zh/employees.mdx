title: 从工作经验到员工能力
description: 理解职责、技能、知识与待确认改进方案的关系。
---

数字员工包含可复用的定义和配置；实际协作还涉及当前成员的授权、员工状态与工作上下文。以下按现行创建页面介绍，不把“生成方案”“保存定义”和“真实完成工作”混为一谈。

## 从员工目录开始 [#start-in-the-employee-directory]

在员工目录选择“创建员工”，进入独立创建页。页面提供“直接填写定义”和“从工作经验学习”两种方式。前者适合职责已经清楚的工作；后者适合已有可复用经验、希望据此起草指令的情况。

目录中的可见范围与个人已经使用的员工不是同一回事。浏览到共享定义，不代表已经拥有它依赖的外部系统访问权限。

## 直接填写定义 [#define-an-employee-directly]

先填基本信息，再说明员工如何工作：

| 字段 | 填写目的 |
| --- | --- |
| 名称 | 让团队能辨认职责，例如“反馈分析助手” |
| 可见范围 | 决定定义在哪个范围可见；选项受管理权限约束 |
| 简介 | 用一句话说明擅长的任务，便于目录查找；可选 |
| Prompt | 工作指令：处理什么输入、遵循哪些步骤、输出什么，以及何时请求确认 |
| 模型 | 从当前可用模型中选择；执行方式会据此适配 |
| 扩展能力 | 按需要关联可用能力，不以选中代替真实授权 |

名称、Prompt 和可用模型是提交前必须满足的条件。页面已带入可用默认模型时，不必重复手选；没有可用模型时，提交会显示字段错误，不能仅凭按钮可点击推断条件已齐。选择公开范围需要相应管理权限。不要为了方便把全部企业知识或所有工具都加入员工；先从职责所需的范围开始。

点击“创建员工”后，核对保存结果和详情。当前页面采用保存生效的合同，不需要再寻找一个并不存在的统一“发布员工”步骤；是否能够实际执行，仍取决于依赖和授权。

## 从经验起草员工 [#draft-an-employee-from-experience]

1. 切换到“从工作经验学习”，填写希望形成的职责目标。
2. 在来源列表选择可用经验，检查标题、所属员工、版本、内容与适用范围。不可复用、待验证、已排除或版本变化的来源会说明原因。
3. 点击“分析所选经验”，查看分析状态与返回方案。分析需要目标和至少一项有效来源，不会仅因打开页面就执行。
4. 审阅建议名称、职责及来源，选择“使用方案，编辑员工”，返回完整表单继续修改。
5. 补齐模型、能力与可见范围，最后明确创建。

这里的“使用方案”只更新当前草稿，不会自动雇佣员工或开始工作。如果表单已有内容，替换名称、简介和指令前会要求确认；模型、头像、能力和可见范围保留。

## 改进已有员工 [#improve-an-existing-employee]

已有员工的训练入口与新建草稿不同。“训练员工定义”围绕指定员工选择经验、填写训练目标并审阅方案；只有明确确认后才开始保存训练成果。当前确认文案为“确认训练并保存成果”，不要沿用旧版一概要求另行发布的说明。

观察操作是否完成、成果是否实际保存，以及目标员工的配置。已有工作保留启动时的配置快照，不能把新配置保存成功解释为正在执行的工作已即时改用新方法。

## 检查一次真实协作 [#check-a-real-collaboration]

员工详情可查看工作记录、记忆和召回等信息。具备相应状态的员工可以开始协作；开始协作进入 SkyBot 并携带员工上下文，访客仍需提供工作目标。来源会话与经验条目应能互相对应，不把别人的历史记录当成新员工自己的经历。

POC 建议：用另一项范围相近的工作检查输出与方法是否适用，记录人的验收结论。软件保存配置，不会自动证明训练效果，也不是修改底层模型参数。

## 常见问题 [#common-issues]

- **模型列表为空**：联系管理员核对可用模型；读取失败时使用重试，保留已填内容。
- **经验无法选择或方案无法使用**：查看来源状态，重新选择并分析，不绕过来源检查。
- **训练被拒绝或配置冲突**：核对目标员工状态、权限与最新定义，再从当前页面重新发起；不要据此重复创建多个员工。

有关可复用资料的发布与核对，见[企业知识](/zh/docs/knowledge)。
