项目用于围绕一个持续目标组织会话、代码仓库与执行上下文。它与正式研发 Task 的用途不同：在项目里讨论或派发 Thread，不会自动在 Tasks 列表生成一条同名任务。

## 何时使用项目 [#when-to-use-a-project]

适合使用项目的情况包括：同一主题需要反复补充背景、多项工作共享资料，或者希望保留主会话与后续执行的关系。一次简短询问可以使用普通会话；需要冻结流程、阶段和工程交付时，阅读[研发任务](/zh/docs/tasks)。

本页按当前源码中的项目工作面介绍。持续输入与协调涉及控制面和执行端配合，不能仅凭新版 Console 已显示入口，就假定既有环境的运行端已同步升级。

## 创建一个项目 [#create-a-project]

1. 进入 SkyBot 工作面，在侧栏 Projects 区域选择“新建项目”。
2. 填写“项目名称”，使用能反映长期目标的名称，例如“客户接入体验改进”，而不是某次执行的状态。
3. 需要代码上下文时，在仓库配置中选择已授权连接与仓库，检查目录等配置是否有效。没有代码工作的项目不必为形式补一个无关仓库。
4. 明确提交创建，查看项目是否出现在侧栏，再进入项目会话提供目标。

创建页会检查必需信息与仓库配置。打开空白输入页、选择项目或进入已有会话，不应被当作已经发送工作目标。创建失败时先看页面原因，确认项目是否已出现后再处理，不凭一次网络错误重复建立多个同名项目。

## 交代目标与项目上下文 [#explain-the-goal-and-project-context]

主会话用于掌握目标、接收补充说明、协调执行与汇总结果。具体实现、命令或测试可交给执行 Thread。开始时说明目标、约束、预期产物与人的决策关口；需要何种资料和连接，仍按当前身份授权。

POC 输入建议：先让主会话整理一份可检查的工作计划，并说明“任何对外通知或生产修改先请求确认”。这是一种评估方法，不是产品会自动对所有动作增加统一审批的保证。

项目中新增讨论、已有主会话与执行 Thread 承担不同职责。查看进展时先确认自己所在的会话，不要把普通讨论中的一句完成回复当成所有后台工作都已结束。

## 运行中补充说明 [#add-instructions-while-work-is-running]

在支持主会话持续输入的环境中，可以在工作推进时补充目标或追问进度。观察消息回执：已接收、已交给主会话与实际完成操作是不同事实。

如果界面表示处理结果未知，保留原消息并核对状态，不自动另开会话重发相同要求。修改已经开始的执行配置也可能受到限制；不要把模型或能力选项变化理解为当前后台工作已无缝迁移。

停止当前主会话的协调轮，不等于取消全部执行 Thread，也不能撤回已经发生的外部操作。需要停止具体后台工作时，到对应工作或 Thread 的受管入口确认状态。

## 查看结果与维护项目 [#review-results-and-maintain-the-project]

查看主会话给出的汇总后，继续打开相关 Thread、工具记录和产物，检查是否对应原目标。执行结束与人工接受分别判断；需要返工时，在同一上下文中交代具体差异与约束。

项目设置可以管理项目信息和仓库。归档用于结束活跃项目的展示与使用；归档和删除不是同一个动作，也不应被当成停止所有执行的快捷方式。操作前保留仍需追查的工作来源。

## 常见问题 [#common-issues]

- **项目入口不可用**：检查工作区、当前执行环境与云环境可用性；不要改用他人身份绕过。
- **项目消失或链接打不开**：核对是否归档、权限是否变化，先重读项目状态，不自动新建替代品。
- **主会话停止后仍有工作运行**：逐项检查执行 Thread，而不是反复点击主会话停止。
- **有产物但没有任务记录**：项目 Thread 与正式 Task 是不同对象，这是正常边界。

验收之后，需要共享的资料可整理到[企业知识](/zh/docs/knowledge)，适合复用的方法可继续用于[数字员工](/zh/docs/employees)。
