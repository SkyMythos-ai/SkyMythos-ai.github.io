当企业从“个人试用大模型”迈向“团队日常生产”，瓶颈往往不在于模型本身不够聪明，而在于**缺少一套将目标、上下文、工具权限、隔离执行环境与结果验收串联起来的工程治理底座**。SkyMythos 旨在扮演这一底座——企业级 **AI-Native Harness**。

## 为什么企业需要 AI-Native Harness [#why-enterprises-need-an-ai-native-harness]

在缺乏统一 Harness 治理的情况下，AI 协助日常业务与软件研发通常会遇到六个结构性难题：

1. **过程不可复现**：Prompt、模型版本、参考文档与工具配置随临时会话不断漂移，同一项工作换人或换天发起便无法稳定复现。
2. **长对话协作失控**：问题理解、方案规划、具体实施、评审与交付挤在同一个上下文不断膨胀的对话窗口中，上下游依赖与失败边界模糊不清。
3. **生成内容离真实交付仍有距离**：AI 输出一段文本或代码片段，不等于形成经过校验、附带来源依据、可供负责人直接审阅签收的交付物。
4. **组织经验随个人会话散失**：有效的排查思路、业务规范和架构决策沉淀在个人聊天记录或零散文档中，新人和后续任务仍要反复从头摸索。
5. **安全治理只能依赖“提示词自律”**：若凭据、代码库与外部写入权限缺少平台级边界控制，一旦上下文被污染或工具误触发，风险将直接落地。
6. **执行过程是黑盒**：团队难以实时观测 Agent 正在调用什么工具、停留在哪个环节、为何失败以及 Token 成本花在哪里。

## 核心命题：让 AI 完成工作，让能力留在企业 [#core-proposition]

SkyMythos 的核心设计哲学可以概括为：**把一次性的会话交互，升级为“目标可冻结、过程可观察、结果可检查、能力可复利”的企业生产方式。**

<HarnessClosedLoopDiagram />

在这个闭环中，所有工作都遵循五项基本原则：

- **先确定目标与边界，再启动执行**：区分探索型对话与结构化交付任务，任务发起前显式绑定所需资料、仓库基线与人工决策关口。
- **执行环境与权限分离**：共享一个数字员工或知识库定义，绝不等于共享创建者的私人密钥；每个人的操作始终受限于自身身份授权。
- **以可检查产物交接，而非仅凭文本结论**：研发任务以代码变更、门禁检查结果与产物摘要交接；知识工作以带原文引用的报告交付。
- **区分 AI 执行完成与人的业务验收**：工作状态结束、自动校验通过、人工业务接受、代码合并与生产部署是五个彼此独立的事实。
- **人确认后再沉淀**：只有经过人审核确认的方法与事实，才整理为数字员工技能提案或发布为团队知识版本，不把原始会话流水账自动当成权威资产。

## 与传统对话式 AI 助手的对比 [#comparison-with-chat-assistants]

| 对比维度 | 传统对话式 AI 助手 | SkyMythos（AI-Native Harness） |
| --- | --- | --- |
| 工作入口 | 单一聊天窗口，所有工作混杂在会话流中 | 按场景区分 SkyBot 项目、研发 Task、自动化 Run 三大工作面 |
| 上下文管理 | 每次手动复制粘贴文档和背景说明 | 按工作空间授权实时召回已发布知识，任务启动时冻结能力与输入规格 |
| 执行环境 | 本地桌面或无状态容器，缺少统一治理 | 一人一持久化开发机 + 一任务一隔离 Sandbox，受集群网络策略约束 |
| 协同与编排 | 单个长会话从头做到尾 | 支持 Flow/WorkNode 多阶段 DAG、Artifacts 契约交接与定向返工 |
| 经验与知识沉淀 | 散落在个人历史聊天里，难以复用 | 形成待人工审阅的数字员工训练提案与带版本溯源的企业知识库 |
| 可观测与成本 | 黑盒生成，难追溯工具调用和阶段耗时 | 全链路关联业务对象与 OpenTelemetry Trace/Span、Token 用量与费用 |

## 外部生态协作边界 [#ecosystem-boundaries]

SkyMythos 聚焦“从目标与资料输入到可审查成果交付”的工作推进环节，设计与企业既有工具链协同工作，而不强行替代企业成熟基础设施：

- **不替代代码托管与评审平台**：与 GitHub、GitLab 等既有代码仓库协同工作；Task 产出代码 Diff 与 PR/MR 建议，最终代码合并仍走团队既有评审机制。
- **不替代通用 CI/CD 与生产发布平台**：Sandbox 内执行的是任务级确定性门禁（Unit Gate）与构建验证，不取代 Jenkins、GitHub Actions 或 Argo CD 等全量发布流水线。
- **不将企业 IM 强行绑定为唯一入口**：支持对接飞书 / Lark、Slack 等企业身份与文档拉取，同时提供完整的独立 Web Console 工作台。
- **不将“私有部署”等同于零数据出境**：私有部署控制权在企业内网，但是否调用外部 LLM Gateway、外部代码托管或第三方连接器，由企业管理员按接入清单逐项核定。
