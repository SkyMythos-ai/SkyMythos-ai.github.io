企业知识库不仅支持在 Console 内在线起草文档，还提供团队多人协作维护、外部文档受控导入与健康度质量监控能力，确保团队资料持续鲜活、可信。

## 工作空间协同维护与权限边界 [#workspace-collaboration-and-roles]

在 `Workspace Knowledge Base` 中，团队成员按照各自工作空间角色分工协作：

- **内容起草与审阅**：拥有维护权限的成员均可编辑文档草稿并记录维护人；发布新版本时保留清晰的历史版本谱系，避免多人同时编辑造成静默覆盖（出现保存/发布冲突时，先刷新读取最新版本再合入改动）。
- **外部资料的只读边界**：通过外部连接器同步进来的文档与手工维护文档在编辑权限上有所区分。外部来源内容一般不允许直接在本地冒充源系统覆盖发布，当源文档更新时应通过重新同步获取最新修订。

## 飞书 / Lark 指定文档拉取与同步任务 [#lark-doc-sync-and-jobs]

<Steps>
  <Step>
    ### 确认前置授权

    首先确保组织管理员已在[飞书 / Lark 接入指南](/zh/docs/im-integration)中启用文档授权（含 `docs:document.content:read` 与 `offline_access`），且已由管理员完成内容授权。
  </Step>
  <Step>
    ### 输入明确 Docx URL 单篇导入

    当前版本支持 Workspace Admin 在知识库同步入口输入一个明确的飞书 / Lark Docx URL，将正文拉取并转化为受控 Markdown 文档。**系统不会擅自扫描整个外部企业网盘，也不声称自动镜像外部权限树。**
  </Step>
  <Step>
    ### 在同步任务视图跟踪进度

    进入二级导航 `知识同步`（`knowledge/sync`），可集中查看各次外部拉取任务的状态、目标知识库与失败原因详情，修正链接或授权异常后可按单任务重跑。
  </Step>
</Steps>

- **识别过期与无来源文档**：重点检查长期未更新、缺少维护者声明或与最新产品决策相矛盾的文档，优先修改草稿并发布新版本，然后重新验证关键检索问题。
- **妥善归档而非暴力删除**：对于已经作废但历史任务曾引用的旧文档，建议先核对引用影响范围后再进行归档处理，既阻止新任务误召回过期规则，又保留历史审计回溯路径。
- **严防流水账污染知识库**：不要把未经提炼和人工审核的完整聊天日志直接导入权威知识库；会话经验请交给[记忆（Memory）](/zh/docs/memory)或[数字员工](/zh/docs/employees)的审阅通道处理。
