企业知识库（Knowledge）将团队文档、版本发布历史与受控检索链路联系在一起。SkyMythos 严格区分**保存草稿、发布版本、完成索引**与**被实际采用**四个环节，确保每一条进入 AI 工作上下文的结论都有源可查。

## 四档知识库范围与访问矩阵 [#knowledge-scopes-and-permissions]

进入一级导航的 **知识库**（`knowledge`），可以看到当前工作空间有权限访问的资料集合。平台按所有权与可见性划分四档范围：

| 范围类型 | 所有权归属 | 读写与管理权限 | 典型用途 |
| --- | --- | --- | --- |
| 个人知识库（Personal Knowledge Base） | 单个 User | 仅本人可见与编辑，除非显式对外共享 | 个人研究笔记、私有参考资料整理 |
| 工作空间知识库（Workspace Knowledge Base） | 所在 Workspace | 按 Workspace 成员角色协作维护与检索 | 团队规范、项目架构决策、客户反馈档案 |
| 共享访问知识库（Shared Knowledge Base） | 原 User 或其他 Workspace | 仅向当前主体开放授权范围，不改变原所有权 | 跨团队只读引用上游部门发布的制度文档 |
| 公开市场发布（Public Knowledge Release） | 原维护者（发布快照） | 同 Org 已登录成员可发现并只读引用不可变 Release | 全公司通用的安全基线、入职手册、技术标准 |

<Callout type="info" title="内容范围与媒体格式支持">
  当前 Knowledge 数据面支持**文本（Markdown/纯文本）、PDF 与图片**的解析与索引；对于通过飞书 / Lark 同步的企业文档，当前支持由 Workspace 管理员输入明确的 Docx URL 拉取为受控正文，不默认扫描整个外部知识空间或继承外部 ACL。
</Callout>

## 文档起草、发布与索引监控 [#create-publish-and-index]

<Steps>
  <Step>
    ### 新建或上传文档资料

    在有管理权限的知识库目录中点击新增，选择在线新建文档、上传文本/PDF/图片，或按支持方式建立目录。建议在正文中标明适用场景、事实依据、维护责任人与需复核条件。
  </Step>
  <Step>
    ### 保存草稿（Save Draft）

    编辑完成后点击“保存草稿”并确认保存成功提示。尚未点击保存的本地编辑器改动不会持久化，也不会影响在线版本。
  </Step>
  <Step>
    ### 单篇发布新版本（Publish Release）

    进入文档详情点击“发布新版本”并确认。发布操作基于**已保存的草稿**生成不可变历史版本，并以单篇文档为单位进行（不会一键将整库未校验草稿打包成同一版本）。
  </Step>
  <Step>
    ### 核对异步索引状态

    发布受理后，后台通过独立 Embedding Gateway 与 LightRAG 执行解析和向量化。在文档列表中核对状态流转：`未发布` → `处理中` → `可检索`。若出现 `失败`，先查看详情错误原因（如 Embedding 网关或文档解析异常）并修正后再点重试；`未知` 状态表示缺少确认信息，不可视为索引成功。
  </Step>
</Steps>

## 使用检索测试与原文回溯 [#retrieval-testing-and-provenance]

正式投入任务使用前，建议利用知识库自带的**检索测试**工具验证召回效果：

1. 进入目标知识库的“检索测试”页签，输入自然语言问题或关键词（例如：“客户反馈优先级由谁拍板确认？”），点击“测试检索”。
2. 系统仅检索该库**已发布且处于可检索状态**的内容（不会搜索尚未发布的草稿）。
3. 检查每条返回结果的标题、匹配片段、关联版本号与召回评分。点击结果标题即可打开**对应历史或当前版本原文**，核对上下文是否完整支持你的业务判断。

<Callout type="warn" title="检索匹配度不代表业务正确性">
  高匹配分只表示文本语义接近，不能替代人工审阅原文前后文。来自外部同步渠道的文档若存在只读限制，请回到源系统更新后再同步，避免在本地复制伪造版本。
</Callout>

## 知识同步、质量分析与过期维护 [#sync-quality-and-lifecycle]

- **同步任务与质量分析**：通过二级导航中的 `知识同步`（`knowledge/sync`）与 `质量分析`（`knowledge/quality`），管理员可追踪外部资料同步记录并识别待清理或低健康度文档。
- **更新与过期版本治理**：更新知识时，先修改草稿再发布新版本，并对关键业务问题重新测试检索。历史引用仍指向其当时的独立版本身份；若某份资料永久失效，请在核对影响范围后进行归档，而不是直接暴力删除团队仍在引用的知识库。
- **严守 Knowledge 与 Memory 边界**：后台自动从会话中提炼出的候选记忆（`Memory Candidate`）仅供个人偏好或项目线索参考，在未经人工核验与整理前，不应把全部历史聊天记录直接灌入团队权威知识库。

若检索测试无结果或索引持续失败，请检查[模型网关、协议与个人凭据](/zh/docs/models-tools)中的 Embedding 配置，或查看[常见问题与故障排查手册](/zh/docs/troubleshooting)。
