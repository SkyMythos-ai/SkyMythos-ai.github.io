SkyBot 是绝大多数日常工作的起点。它同时承载轻量级的 **Quick Chats（即时对话）**与面向长期目标的 **Projects（项目协作）**，让你在同一个上下文中不断补充资料、调动数字员工并检查交付产物。

## 选型对照：Quick Chats、Project 与研发 Task [#choosing-between-chats-projects-and-tasks]

| 对比维度 | Quick Chats（即时对话） | Project（长期项目） | 研发 Task（工程任务） |
| --- | --- | --- | --- |
| 适用场景 | 单次咨询、快速文档分析、临时代码解释 | 跨多天推进的持续目标、需共享工作目录与项目记忆的协作 | 需求明确、要求冻结流程与测试门禁的代码交付 |
| 文件与目录 | 聚焦当前会话自身上下文 | 同一 Project 下多个会话共享固定项目工作目录 | 在一任务一隔离 Sandbox 内拉取指定分支运行 |
| 流程确定性 | 自由对话推进，按 Turn 记录事件 | 主会话协调目标，可将子工作派发给执行 Thread | 按发布版本 Flow/WorkNode DAG 与 Unit Gate 推进 |
| 对象边界 | 不出现在正式研发 Task 列表 | 项目 Thread 不会自动转换为研发 Task | 生成独立 TaskSpec 与不可变 Artifact 交付物 |

## 创建与配置一个项目 [#create-and-configure-a-project]

<Steps>
  <Step>
    ### 进入 SkyBot 并新建项目

    打开一级导航中的 **SkyBot**，在二级侧栏的 `Projects` 区域点击“新建项目”。
  </Step>
  <Step>
    ### 规范项目名称与长期目标说明

    使用能够清晰表达长期主题的名称（例如“客户接入体验改进”或“结算服务重构专项”），而不是单次动作或日期流水号，并填写项目简介。
  </Step>
  <Step>
    ### 按需关联已授权代码仓库

    若项目涉及源码阅读或变更分析，在仓库配置中选择你已有权访问的 Git 连接与具体代码仓库，并核对工作目录配置。纯业务分析类项目无需强行绑定无关仓库。
  </Step>
  <Step>
    ### 确认创建并进入项目主会话

    点击提交后，核对侧栏已出现该项目条目，再进入项目主会话输入首轮工作目标。打开空白项目页面并不代表已经发起任何执行。
  </Step>
</Steps>

## 在项目上下文中高效协作 [#collaborate-effectively-in-projects]

### 1. 交代目标与项目上下文 [#explain-the-goal-and-project-context]

项目主会话负责理解长期目标、接收后续补充说明并汇总进展；具体的长耗时分析、文件整理或命令执行可由执行 Thread 分担。首次发令时，建议让主会话先梳理可检查的工作计划，并显式约定需要人工拍板的边界（例如：“对外发送邮件或变更线上配置前先请求我确认”）。

### 2. 运行中补充说明与状态核对 [#add-instructions-while-work-is-running]

在支持持续输入的环境中，你可以在主会话推进过程中随时补充新背景或追问进度。注意核对界面回执状态：

- **已接收 / 已交由主会话**：表示你的补充指令已持久化进入当前协调轮次，不代表后台所有动作已完成。
- **处理状态未知**：先保留原消息并刷新查看当前会话状态，避免因为网络抖动连续在多个窗口重复发送互相冲突的指令。
- **停止协调与停止后台任务**：停止主会话当前的协调轮次，不会自动取消已经派发出去的全部执行 Thread，也无法撤回已经发生的外部操作。如需中止具体后台执行，请进入对应工作或 Thread 的受管入口操作。

### 3. 共享目录与项目记忆 [#shared-directory-and-project-memory]

同一项目下的多个会话可以读写共享的项目工作目录，共同利用沉淀下来的**项目记忆**（记录带来源的事实、决策与关键线索）。同时，每个会话依然保持独立的消息历史与思考上下文，避免无关对话互相干扰。

## 成果验收、归档与常见问题 [#review-archive-and-troubleshooting]

查看主会话提供的结果汇总后，请进一步打开关联的 Thread、工具调用记录与生成文件，对照原始目标逐项验收。

<Callout type="info" title="项目归档与删除的区别">
  当一个阶段性目标完成后，可在项目设置中选择**归档**，以收起活跃列表展示同时保留可追查的历史上下文与来源文件。归档不是“一键终止运行中任务”的快捷方式，操作前请先确认项目内已无后台活跃执行。
</Callout>

- **项目入口或云环境提示不可用**：检查当前工作空间权限及个人开发机/沙箱运行状态，勿借用他人凭据绕过检查。
- **主会话已停止但仍有后台运行**：进入各关联执行 Thread 逐项核对并按需停止，而不是反复点击主会话停止按钮。
- **产出了工作文件却在 Tasks 列表找不到记录**：项目 Thread 与正式研发 Task 是两套独立业务对象，属于正常边界设计。若需冻结规格并触发研发门禁交付，请前往[研发任务（Tasks）](/zh/docs/tasks)发起正式任务。

项目中验证有效的资料可直接沉淀到[企业知识库](/zh/docs/knowledge)，可复用的协作角色可以进一步固化为[数字员工](/zh/docs/employees)。
