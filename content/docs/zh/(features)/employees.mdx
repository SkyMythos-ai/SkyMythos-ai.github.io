description: 为不同职责配置数字员工的指令、模型与工具，并通过工作经验分析与人工确认实现安全的能力进化。
---

数字员工（AI Employee）将企业中高频、标准化的岗位方法沉淀为可复用的资产配置。在团队内部共享数字员工定义时，每个成员依然使用各自独立的执行上下文与授权范围，确保职责复用与安全边界兼得。

## 数字员工的能力结构 [#employee-capability-model]

进入一级导航的 **数字员工** 目录（`my-ai?section=employees`），你可以浏览当前工作空间或组织公开的员工定义，并点击“创建员工”进入独立创建页面。每位数字员工由六部分组成：

| 配置字段 | 作用与填写规范 |
| --- | --- |
| 名称（Name） | 清晰表达岗位职责，例如“客户反馈分析助手”或“安全合规初审专员”。 |
| 可见范围（Visibility） | 决定定义在个人、工作空间还是组织公开范围可见；公开范围受管理权限约束。 |
| 简介（Description） | 一句话概括擅长场景与输出风格，便于团队在目录中检索选用（可选）。 |
| 工作指令（Prompt） | 明确接收什么输入、遵循哪些分析步骤、交付何种结构、何时必须向人请求确认。 |
| 基础模型（Model） | 从当前部署已启用的兼容模型目录中选择，系统会据此适配运行协议。 |
| 扩展能力（Capabilities） | 按需关联相关知识库、Skill 或 MCP 工具；只授予职责确实所需的最小范围。 |

<Callout type="info" title="保存生效与执行前提">
  在当前创建表单中填写完整名称、Prompt 与可用模型后点击“创建员工”，配置会立即保存生效（无需再寻找一个独立的“统一发布员工”按钮）。目录可见不等于自动拥有其依赖工具的外部访问权，实际运行时仍会校验当前执行人的授权状态。
</Callout>

## 创建数字员工的两种方式 [#two-ways-to-create-an-employee]

<Tabs items={["直接填写定义", "从工作经验起草"]}>
  <Tab value="直接填写定义">
    适用于职责流程已经非常明确的场景：

    1. 在创建页选择“直接填写定义”。
    2. 填写名称、可见范围与简介，重点编写结构化的工作指令（Prompt）。
    3. 核对默认带入或手动选择可用的基础模型，按最小必要原则勾选关联知识与工具能力。
    4. 点击“创建员工”并确认保存结果。

    可以参考以下指令结构编写员工 Prompt：

    ```text
    角色定位：你是研发与产品团队的客户反馈归因助手。
    输入要求：接收原始反馈记录与关联版本说明，不编造未提供的数据。
    执行步骤：先按问题域归类，再检索《产品规范》知识库核对当前设计意图。
    交付格式：输出 Markdown 问题清单，每条必须附带来源链接与建议验收项。
    确认边界：涉及对外回复客户或变更工单优先级时，先形成建议并等待人确认。
    ```
  </Tab>
  <Tab value="从工作经验起草">
    适用于团队已经在 SkyBot 或项目中跑通了优秀案例、希望据此总结新员工的场景：

    1. 切换到“从工作经验学习”，填写希望形成的新员工职责目标。
    2. 在来源列表中查看可用经验的标题、所属员工、版本、正文与适用条件（不可复用、待验证或已排除的来源会附带状态说明）。
    3. 选中一条或多条有效经验后点击“分析所选经验”，等待分析完成并审阅返回的建议名称、职责与来源引用。
    4. 点击“使用方案，编辑员工”将草案带入完整表单；若表单已有内容，系统会在替换名称、简介与指令前请求确认，并保留你已选的模型与扩展能力。
    5. 补全模型、能力与可见范围后提交创建。
  </Tab>
</Tabs>

## 训练已有员工与经验进化边界 [#train-existing-employees-and-boundaries]

对于已经投入使用的数字员工，可以在其详情页使用**“训练员工定义”**入口持续优化：

<Steps>
  <Step>
    ### 选取经验并设定训练目标

    针对目标员工选择经过核验的工作经验条目，写清本次希望强化的步骤、约束或输出格式目标。
  </Step>
  <Step>
    ### 审阅生成的改进方案

    系统基于所选经验形成待审阅的能力修改建议。此时尚未改变员工线上配置，你可以逐条比对原指令与建议差异。
  </Step>
  <Step>
    ### 显式确认并保存成果

    核对无误后点击**“确认训练并保存成果”**，新的职责指令即刻保存至员工定义。
  </Step>
</Steps>

<Callout type="warn" title="关于“员工训练”的工程事实">
  这里的“训练”是指从工作经验中提炼并更新数字员工的 Prompt 指令、方法规则与能力装配，**不是修改底层大语言模型的神经网络权重**。同时，正在执行中的任务会继续持有启动时的配置快照，不会因为保存了新配置而被中途篡改行为。
</Callout>

## 开始真实协作与排查建议 [#start-collaboration-and-troubleshooting]

在员工详情页，你可以查看该员工的历史工作记录（Records）、记忆（Memory）、经验（Experience）与知识召回记录。点击“开始协作”将带着该员工上下文进入 SkyBot 工作面，随后输入本次具体任务目标即可启动。建议在正式推广前，先用一项与经验来源范围相近的小任务实测输出质量，并记录人工验收结论。

- **模型列表为空或提交报错**：请管理员确认网关模型目录已启用；若是网络读取失败，点击表单重试按钮而保留已填内容。
- **经验条目不可选或无法应用**：核对来源状态说明（如待验证或版本已变更），重新选择有效来源进行分析。
- **训练保存报配置冲突**：刷新读取目标员工最新定义与状态后再重新发起训练，避免为此重复创建多个同名员工。

关于如何沉淀供数字员工检索的长期资料，请继续阅读[企业知识库与记忆体系](/zh/docs/knowledge)。
