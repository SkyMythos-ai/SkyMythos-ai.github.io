**自动化（Automations）** 面向周期性或事件驱动的重复工作（如每日反馈汇总、定时巡检简报、Webhook 触发预处理等）。平台严格区分**自动化流程定义（Definition）**与每次触发产生的**实际运行实例（Run）**——前者描述规则与方法，后者记录当次输入、执行步骤与真实输出。

<Callout type="info" title="与研发 Tasks Flow 的边界">
  Automations（`agents/flows`）与研发任务（`tasks` / `flows`）服务于不同工作面，两者的流程配置不可直接互换。首次接入某类重复任务，建议先用“根据给定数据生成待审阅摘要”进行手动试运行，确认产出稳定后再开启定时或外部事件触发。
</Callout>

## 配置流程任务与运行环境 [#configure-tasks-and-the-environment]

进入一级导航 **自动化**（`agents/flows`），点击“新建流程”。编辑器支持**单 Agent** 与**多 Agent** 两种编排模式（第一次建议优先使用单 Agent，避免为了形式增加多余空步骤）：

| 配置项目 | 填写要求与协同逻辑 |
| --- | --- |
| 流程名称 | 让操作者一眼识别该自动化所承担的业务目的 |
| 任务指令 | 写清接收什么输入参数、按何种步骤处理、输出结构及何时必须等待人确认 |
| Agent 与扩展能力 | 选择胜任该任务的数字员工及所需 Skill / MCP 能力 |
| 运行环境与变量 | 指定运行环境与受控环境变量引用；多 Agent 流程下未单独覆盖的步骤继承默认环境 |
| 触发方式 | 支持手动运行、Cron 定时调度、Webhook 回调或当前可用连接器事件 |
| 结果去向 | 按需选择已授权的结果发送目标，也可仅保留在 Run 产物中不对外推送 |

当多 Agent 步骤需要引用前一步产出时，请使用页面提供的**步骤结果插入入口**并确认前置依赖关系；在指令中声明的参数会自动形成运行时输入表单。需要引用的环境变量如果显示缺失，应回到环境配置补齐或修正引用，切勿在指令正文粘贴密钥。

## 保存生效与试运行校验 [#save-and-test-a-workflow]

SkyMythos 对编辑中的草稿和可运行配置进行分离管理：

1. **保存即生效**：完整填写任务、环境与能力配置后点击“保存”，前端校验必填条件，服务端继续核验当前执行授权，形成可运行版本（当前界面无需再找一个独立“发布”按钮）。若原配置处于暂停状态，保存修改不会自动代为恢复触发。
2. **试运行（Test Run）**：在未形成正式版本前或更新草稿后，可使用试运行入口并通过表单或 JSON 准备输入参数进行验证。试运行仍会严格校验当次草稿、必填输入、运行环境与授权条件。

<Callout type="warn" title="试运行并非无副作用沙盘">
  当前试运行不会触发流程末尾的“结果发送通知”，但运行过程中依然可能真实调用所绑定的外部工具并产生动作。请务必使用已授权的测试或 POC 资源进行试运行。
</Callout>

## 配置定时、Webhook 与事件触发 [#add-a-schedule-or-event]

<Tabs items={["定时触发（Schedule）", "Webhook 触发", "连接器事件（Events）"]}>
  <Tab value="定时触发（Schedule）">
    配置调度周期时，务必同时核对**执行频率、触发时刻与目标时区**。已保存的定时配置会保留其保存时指定的时区设置，不会因为操作者更换电脑或浏览器时区而被悄悄改写。
  </Tab>
  <Tab value="Webhook 触发">
    Webhook 回调地址与签名校验密钥均由**已保存的可运行配置**生成（未保存的草稿不会生成可用地址）。签名密钥仅向具备相应管理权限的人员展示，切勿把含完整密钥或签名地址的截图直接外发。
  </Tab>
  <Tab value="连接器事件（Events）">
    选择当前部署已接通的企业连接器、具体事件类型、过滤条件与参数映射规则。事件准入模块会消费路由规则、复核准入条件后才创建 Run 实例。配置完成后应触发一条真实样本事件并检查对应 Run 记录，分别核对“规则已保存”“事件已受理”和“业务输出正确”三件事。
  </Tab>
</Tabs>

## 追踪每次 Run 与异常处理 [#read-individual-runs]

在 `运行历史`（`agents/runs`）中打开单次记录，逐项检查实际传入参数、各步骤耗时、工具记录、最终输出与等待确认项：

- **等待人工决策**：优先在当前 Run 详情中处理暂停确认事项，确认后流程继续向后推进。
- **失败重试与取消**：失败或取消后点击“重新运行”，会基于原输入发起一条**全新的 Run**，保留旧记录供追溯；运行中请求取消只表示发送了停止信号，已经执行的外部工具动作无法自动撤回，也不同于暂停整个流程触发器。
- **状态未知的恢复**：若提交后遇到网络超时或状态未明，先核对原次 Run 状态再决定恢复操作，避免重复创建多条相同 Run。成本统计如显示未提供或未知，不代表零费用消耗。

关于全链路的追踪与 Token 开销分析，请继续阅读[统一可观测性与成本分析](/zh/docs/observability)。
