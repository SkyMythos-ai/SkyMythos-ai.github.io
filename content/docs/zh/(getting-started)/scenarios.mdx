SkyMythos 既可以处理一次性的文档整理与分析任务，也可以承载跨周推进的软件研发和定期自动化运转。以下按五大业务与技术维度列出常见落地场景。

## 一、日常办公与职能协作 [#daily-office-and-business-ops]

面向行政、HR、财务、法务、销售、市场与产品团队的高频非编码工作：

| 场景名称 | 适用说明 | 推荐配合能力 |
| --- | --- | --- |
| 客户反馈归因与总结 | 对多渠道脱敏反馈文本进行分类归因，对照产品规范输出带原文来源的改进清单 | SkyBot 项目 + 知识库检索 |
| 制度问答与合规核对 | 基于《员工手册》《差旅制度》或内控基线回答员工咨询，明确引用对应章节版本 | 知识库发布版本 + 数字员工 |
| 业务文书与纪要起草 | 根据会议纪要、沟通记录与范本条款，生成待法务/HR 审定的文书初稿与材料清单 | 数字员工 + 知识库 |
| 经营与财务数据辅助分析 | 整理结构化表格与报表摘要，提炼异常波动项并列出需人工复核的条目 | SkyBot 对话 / 自动化 |
| 销售方案与资料组装 | 快速检索脱敏产品白皮书、FAQ 与授权案例，形成面向客户的沟通要点与回应草案 | 知识库 + 飞书/Lark 连接器 |
| 周度简报与信息汇总 | 按固定周期自动读取指定输入源并生成待审阅简报，降低人工重复整理耗时 | 自动化（Automations） |

## 二、软件研发与工程交付 [#software-engineering-delivery]

面向研发工程师、架构师与技术负责人，在隔离环境中完成可审查的代码与工程产出：

| 场景名称 | 适用说明 | 推荐配合能力 |
| --- | --- | --- |
| 明确需求端到端交付 | 从需求正文或 Git Issue 出发，经理解、实现、自测门禁交付完整 Git Diff 与 MR 摘要 | 研发任务（Tasks）+ Flows |
| 单元测试与校验补全 | 为已有接口或核心函数补充边界单测与参数校验，运行确定性单测门禁验证 | 研发任务（Tasks）+ Unit Gate |
| 代码审查初筛与影响分析 | 在隔离沙箱内比对基线分支改动范围，结合仓库规范检查潜在风险并输出审查意见 | WorkNode + 规范 Skill |
| 个人持久化开发机协同 | 在绑定独立 PVC 的个人开发机中使用 Web Terminal 与完整工具链持续编码调试 | 个人开发机（Dev Machines） |
| 缺陷复现与故障线索排查 | 结合报错日志、可观测链路和仓库代码定位根因线索，整理修复方案供工程师审阅 | SkyBot + 可观测性 |

## 三、持续项目协作 [#ongoing-project-collaboration]

当一项工作无法在一轮对话内结束，需要不断补充背景材料并协调多项子任务时：

- **共享项目工作目录**：在 SkyBot 项目内多次开新会话分析同一批设计稿或业务数据，避免反复上传同一组文件。
- **沉淀项目记忆**：将项目推进过程中双方拍板的约束条件、关键结论保留为带来源的项目记忆，供后续会话延续使用。

## 四、专业数字员工与技能复用 [#specialized-employees-and-skills]

- **岗位职责固化**：将高频任务提示词、推荐模型和最小必要工具组装成专业[数字员工](/zh/docs/employees)，团队成员一键召唤即可按统一口径工作。
- **经验持续进化**：在项目或任务完成后，从有效记录中分析生成改进方案，经人工确认后更新员工指令，让团队工作标准越用越稳。

## 五、企业外部系统协同 [#enterprise-system-integration]

- **Git 仓库连接**：由管理员登记 Git 服务地址，成员绑定个人 Git Token 读取授权仓库并生成变更分支。
- **飞书 / Lark 与 Slack 接入**：支持统一企业身份 SSO 登录，以及由管理员输入明确 Docx 链接将外部文档同步至受控知识库。
- **MCP 标准工具接入**：通过标准化 MCP 服务连接企业内部工单、监控或只读数据查询工具，所有调用留存完整 Trace 证据。
