当工作空间中同时运行着多个项目会话、研发任务与自动化流程时，你可以通过**工作总览（Overview）**、**收件箱（Inbox）**以及各工作面列表统一掌控全局进度。

## 集中查看与筛选工作状态 [#view-and-filter-work]

- **工作总览（`overview`）**：进入工作空间后的默认聚合入口，集中展示近期活跃项目、正在推进的研发 Task 与快捷发起入口。
- **收件箱（`inbox`）**：统一汇总所有需要你回应的动作审批请求（`ActionProposal` / `ActionApproval`）、Agent 运行中提问以及环境升级提醒，无需逐个点进每个会话寻找卡点。
- **分模块列表**：在 **SkyBot 侧栏**按最近对话或项目分组查看，在 **Tasks 列表**按任务状态检索工程任务，在 **Automations 运行历史**按触发时间查看每一次独立 `Run`。

## 读懂五类核心状态 [#understand-core-statuses]

| 显示状态 | 真实含义 | 建议下一步动作 |
| --- | --- | --- |
| **排队 / 已受理** | 控制面已校验输入并创建执行记录，正在分配 Sandbox 或等待调度 | 稍候片刻刷新查看，不重复提交相同任务 |
| **运行中（Running）** | Agent 或 Sandbox 节点正在推进步骤或调用工具 | 可展开会话或节点详情观察实时进度与工具日志 |
| **等待确认 / 输入（Waiting）** | 流程在关键决策点暂停，等待人工批准动作或补充缺失信息 | 在收件箱或任务详情卡片核对影响对象后明确同意或回复 |
| **已完成（Completed）** | Agent 执行回合或 Flow 全部阶段已运行结束 | 打开产物、来源引用或代码 Diff 完成人工业务验收（详见[结果查看](/zh/docs/results)） |
| **失败 / 已取消（Failed / Cancelled）** | 门禁未通过、连接授权失败或被操作者请求取消 | 保留错误现场定位根因，按需使用恢复入口而不是盲目覆盖历史 |

<Callout type="info" title="记住状态边界">
  “沙箱环境就绪”不等于“任务已经完成”，“执行已完成”也不等同于“业务已经验收通过或代码已合并上线”。
</Callout>

## 继续处理、恢复与归档已有工作 [#resume-and-maintain-work]

1. **基于原上下文继续推进**：对于 SkyBot 对话或项目，直接回到原 Thread 补充新约束即可接续工作，不必另起炉灶丢失前文背景。
2. **研发任务定向恢复（`Fusion Resume`）**：当某个研发 Task 在特定 WorkNode 失败或检查门禁未通过时，无需从头重跑整个流水线。修正环境或代码要求后，可在任务详情页从指定节点发起新的 Execution Generation 重试或带提示返工，原有失败证据完整保留。
3. **取消运行 vs 暂停自动化**：取消某一次正在执行的 Automation Run 不会撤销已经完成的外部工具动作；若希望后续不再定时或按事件触发，请在自动化流程设置中暂停该流程。
4. **项目归档整理**：阶段性目标验收结束后，可在项目设置中选择**归档**（归档仅收起活跃展示并保留历史追查记录，操作前应确认后台 Thread 均已结束）。
