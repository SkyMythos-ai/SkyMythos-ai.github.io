在 SkyMythos 中发起工作，不需要一开始就掌握复杂的编排语法。用清晰的自然语言交代清楚目标与边界，再选对工作入口和上下文，就能让数字员工或研发流程准确推进。

## 描述目标：从一句话到四要素模板 [#describe-the-goal]

你可以直接输入一句话需求，也可以在正式工作时按**“目标 + 资料 + 交付格式 + 边界”**四要素组织指令：

- “把这周汇总的客户反馈按模块归类，对照《产品接入指南》整理三项优先改进建议。”
- “结合《员工手册》考勤与调岗章节，起草一份《协商变更岗位确认书》初稿，并列出需 HR 核实的材料。”
- “阅读当前关联仓库的登录模块，分析 OAuth 回调校验逻辑并输出修改建议。”
- “为配置保存接口补充空名称校验和单元测试，保持原有成功响应格式不变，仅交付变更和检查日志。”
- “每周一早上读取指定周报目录，生成待产品负责人审阅的摘要草稿。”

当任务涉及明确验收标准时，推荐使用以下结构化模板：

```text
目标：说明要解决的具体问题或完成的改动。
资料：指定允许检索的知识库名称、上传文件或目标代码仓库与分支。
交付：明确希望输出 Markdown 报告、对比表还是代码变更与测试日志。
边界：写清禁止越界的动作（例如：仅生成初稿、不修改生产配置、不自动合并分支）。
```

## 按任务性质选对工作入口 [#choose-the-right-work-surface]

不同工作入口承担不同职责，创建前请按需选择：

| 你的工作特征 | 选择哪个入口 | 创建位置与要点 |
| --- | --- | --- |
| 一次性分析、问答或快速验证思路 | **SkyBot 即时对话（Quick Chats）** | `SkyBot → 新建对话`，直接描述目标或关联所需知识库即可开始 |
| 同一主题需多轮补充文件、保留目录与记忆 | **SkyBot 项目（Projects）** | `SkyBot → 新建项目`，设置长期名称、工作目录及可选关联仓库（详见[项目](/zh/docs/projects)） |
| 需求明确、要求按流程交付可审查代码变更 | **研发任务（Tasks）** | `研发任务 → 新建任务`，绑定 Repository、Base branch、Flow 与必填参数（详见[研发任务](/zh/docs/tasks)） |
| 按定时周期或外部事件重复执行的固定工作 | **自动化（Automations）** | `自动化 → 新建流程`，配置指令、运行环境、触发器与试运行（详见[自动化](/zh/docs/automations)） |

## 绑定上下文与补充资料 [#attach-context-and-materials]

创建工作时，可以通过四种安全、受控的方式提供上下文：

1. **关联已发布知识库**：仅勾选本次任务真正需要且你有权访问的知识库（注意草稿未发布前无法被检索）。
2. **上传本地文档或截图**：支持上传文本、PDF 与图片材料供当前工作解析处理。
3. **指定代码仓库与基线分支**：在 Project 或研发 Task 中选择已通过个人 Git 凭据授权的仓库，并避开受保护生产分支作为基线。
4. **选择数字员工与能力**：为工作指定合适的[数字员工](/zh/docs/employees)或能力市场中的 Skill/MCP，避免每次重复粘贴冗长规则。

<Callout type="warn" title="不要在输入框中粘贴敏感密钥">
  切勿将模型 API Key、Git Token 或企业应用 Secret 直接写入任务描述或对话内容中。所有访问凭据均应提前在[模型配置](/zh/docs/models-tools)与[连接器](/zh/docs/connectors)中加密保存。
</Callout>

## 创建成功后的界面变化 [#after-task-creation]

提交创建后，工作台会进入对应的执行视图：
- **左侧列表**：新对话、项目或任务会出现在对应工作面列表中，方便随时切换回来查看。
- **中央工作区**：实时展示当前协调轮次、工具调用步骤、阶段状态或等待确认提示。
- **右侧与详情面板**：可随时查看关联的上下文文件、生成产物、代码差异与链路追踪记录。
