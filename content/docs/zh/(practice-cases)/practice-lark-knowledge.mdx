许多企业的核心产品方案、SOP 与复盘文档都沉淀在飞书或 Lark 云文档中。本案例展示如何在确保权限边界的前提下，将关键飞书文档安全引入 SkyMythos 知识库并转化为项目和数字员工的生产力。

## 场景目标与准备工作 [#goal-and-prerequisites]

- **预期交付**：团队重点飞书文档完成受控导入、版本发布与检索测试，并在 SkyBot 项目问答中实现一键回跳来源原文。
- **准备工作**：
  1. 组织管理员已按[飞书 / Lark 与 Slack 接入指南](/zh/docs/im-integration)完成企业应用配置，并开通 `docs:document.content:read` 与 `offline_access`。
  2. 你拥有目标工作空间知识库的管理权（`Workspace Admin` 或授权维护者）以及飞书目标文档的明确 Docx URL。

## 分步操作实战 [#step-by-step-walkthrough]

<Steps>
  <Step>
    ### 1. 完成管理员文档授权并指定 URL 导入

    在目标工作空间知识库的[同步入口](/zh/docs/knowledge-sync)，输入需要引入的飞书 / Lark Docx 明确链接，发起受控导入（系统仅拉取所指定单篇文档为 Markdown，不扫描整个云盘）。
  </Step>
  <Step>
    ### 2. 在同步任务确认结果并发布版本

    进入 `知识同步` 确认拉取任务完成，查看生成的文档内容并核对格式，随后点击**发布新版本**触发异步向量化索引，直至列表状态显示`可检索`。
  </Step>
  <Step>
    ### 3. 运行检索测试验证原文回溯

    进入该知识库的“检索测试”，针对文档中的一条核心规则提问（例如：“接口超时重试间隔规范是多少？”），点击命中结果确认能打开对应发布版本正文核对上下文。
  </Step>
  <Step>
    ### 4. 在日常项目与研发任务中直接消费

    接下来无论在 SkyBot 项目协作还是研发 Tasks 中挂载该知识库，团队成员提问或研发分析都能自动参考这篇经过核验的文档，不再需要手动复制文档内容。
  </Step>
</Steps>

## 维护与更新建议 [#acceptance-checklist]

- **源文档更新后的同步习惯**：当飞书原文档有重要修订时，由管理员重新发起一次该链接的同步拉取并发布新版本，不要在本地复制多份内容相互矛盾的副本。
- **注意访问范围边界**：导入进工作空间知识库后，该文档遵循当前 SkyMythos 工作空间的成员角色权限治理，不会自动同步飞书侧原有的细粒度文档权限。
