对于每周固定发生的“汇总各组进展生成周报草稿”或“周一晨间整理待跟进事项清单”等重复任务，与其每周一手动打开对话复制一遍指令，不如将其固化为一条可追溯的 **Automation**。

## 场景目标与准备工作 [#goal-and-prerequisites]

- **预期交付**：每周一早 09:00 自动生成一份待审阅业务简报，保存在对应 `Automation Run` 记录中（可选配置经授权的消息通知去向）。
- **准备工作**：
  1. 确认已存在可用的运行环境与目标数字员工（例如“周报整理专员”）。
  2. 备好一份脱敏示例输入，用于正式定时前的试运行校验。

## 分步操作实战 [#step-by-step-walkthrough]

<Steps>
  <Step>
    ### 1. 在 Automations 创建单 Agent 流程

    进入 **自动化**（`agents/flows`）点击“新建流程”，命名为“周度业务进展简报”，选择适用运行环境与数字员工，编写任务指令并声明运行时输入参数（如目标知识库/汇总范围）。
  </Step>
  <Step>
    ### 2. 保存并先执行一次试运行（Test Run）

    点击“保存”形成可运行配置，先点击**试运行**填入样本参数。确认试运行产出的简报结构清晰、没有错误调用外部写操作（注意：试运行不发送末尾通知，但过程中会真实调用已绑定工具，务必用测试资源验证）。
  </Step>
  <Step>
    ### 3. 配置定时规则与时区并核查首条 Run

    切换触发方式为定时（Cron），同时核对**频率、具体时刻与时区**（如 `Asia/Shanghai` 每周一 09:00），保存配置。待触发或手动触发一次真实运行后，前往 `运行历史`（`agents/runs`）核对该次 Run 的实际输入、输出与费用明细。
  </Step>
</Steps>

## 验收与运营要点 [#acceptance-checklist]

- **区分配置与运行**：修改或暂停自动化流程时，记得同步查看是否还有正在执行中的单个 `Run`。
- **结果先审后发**：建议简报生成后先由负责人审阅确认，再对外转发或同步给更广范围的团队。
