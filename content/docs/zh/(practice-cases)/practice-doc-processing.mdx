description: 在 SkyBot 项目中结合已发布产品规范与多份客户反馈文件，自动完成归因分类、来源引用绑定与优先级建议输出。
---

当客服、运营或产品团队每周面对数十条分散在 PDF、Markdown 或文本导出的客户反馈时，人工逐条阅读并对照产品规范耗时极高。本案例演示如何通过 **SkyBot 项目 + 企业知识库** 在几分钟内形成带原文依据的归因报告。

## 场景目标与准备工作 [#goal-and-prerequisites]

- **预期交付**：一份按“体验缺陷 / 需求缺失 / 文档引导不清”分类的问题归因清单，每条附带客户反馈出处与产品规范对照链接。
- **准备工作**：
  1. 在工作空间[企业知识库](/zh/docs/knowledge)发布最新版《产品功能边界与接入指南》，确认索引状态为`可检索`。
  2. 准备好本周导出的脱敏客户反馈文档（文本或 PDF，确保移除客户个人隐私与敏感密钥）。

## 分步操作实战 [#step-by-step-walkthrough]

<Steps>
  <Step>
    ### 1. 创建长期项目并上传反馈材料

    进入 **SkyBot**，新建名为“客户反馈归因分析”的 Project，并将本周导出的反馈文件上传到项目工作目录中（这样后续各周也能在同一项目内横向对比变化）。
  </Step>
  <Step>
    ### 2. 发送结构化四要素分析指令

    在项目主会话勾选《产品功能边界与接入指南》知识库后，输入如下指令：

    ```text
    目标：读取项目目录下的本周客户反馈文件，归类并提炼最紧急的 5 项体验改进建议。
    资料：结合我已勾选的《产品功能边界与接入指南》知识库核对当前产品设计意图。
    交付：输出 Markdown 表格，列明问题分类、影响模块、原始反馈片段、对应规范原文依据与建议验证方式。
    边界：仅形成待产品团队评审的报告，不直接修改外部工单系统或对外回复客户。
    ```
  </Step>
  <Step>
    ### 3. 核查结果并开展多轮细化

    查看生成的归因表格后，可针对高优先级条目继续追问：“将第 1 条和第 3 条拆分出可交付给研发团队的需求边界说明”。
  </Step>
</Steps>

## 验收与复盘要点 [#acceptance-checklist]

- **逐条回跳原文**：点击报告中引用的《产品功能边界与接入指南》片段，核对是否真正存在于对应发布版本上下文中。
- **保留人工排期拍板**：最终优先级排序与工单创建仍由产品负责人审核后决定。
