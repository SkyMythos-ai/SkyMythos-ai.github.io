# 设计经验

## 先分清页面职责，再调整动画与排版

- 用户纠正：产品、概念和架构仍混乱，应参考产品 Keynote 重组官网，而不是继续局部修饰。
- 规则：首页回答产品是什么与为什么需要，工作方式页沿同一案例解释如何完成与复用，架构页先给全貌再说明边界，文档承接配置与诊断。每段主要内容有唯一归属，不能用不同图形在多页重讲员工培养。首屏产品定义固定，动画支持同一个主张。
- 边界：对话协作、研发 Task 与 Automation Run 是不同工作方式，不能用一条研发状态机代表全部产品。完整培养过程仍须先记录经验、后人确认与员工形成；已有员工参与工作的概览与培养图分开说明。
- 验证：逐页检查它回答的读者问题及重复内容，使用同一个业务示例贯穿过程；导航、元数据、链接、手机与真实跨页导航一起验收。当前分工见[Keynote 官网页面职责](../research/keynote-website-information-architecture.md)。

## 人与 Agent 先做简洁形象草稿，再接入动画

- 用户纠正：机械人物改成圆润立体造型后仍显诡异；需要简单化，先设计人和 Agent 的形象图片草稿，不能继续直接修改网页动画。
- 规则：亲和不等于增加写实五官、肤质渐变或胶囊关节。先以独立静态稿比较简洁轮廓、比例和辨识度；人保留人的特征，Agent 不必强行拥有人的身体。去掉不必要的肢体、关节、立体材质和装饰，不在尚未认可的形象上继续叠加动作与场景。设计方向确认后再接入已有工作流程。
- 用户进一步纠正：明确要求照原版使用 Grok Bot 时，不要继续改成自己的近似造型，也不要把直接复用的要求替换成“借鉴后原创”。优先核对并使用原始视觉数据，保留用户已选定的其他部分；原站不可访问时说明所用存档来源与核验限制，不把第三方改稿当成官方原版。
- 验证：先看独立大图与实际缩小尺寸，比较人和 Agent 是否清楚、协调且不怪异；图片草稿与已确认方案分开记录。确认后再检查动作、交接与遮挡，类型、构建和几何检查不能替代用户对形象方向的认可。

## 流转轨迹只在实际传输时出现

- 用户纠正：记录归集、经验用于培养员工的轨迹不应一直存在；没有数据流转时不显示线路。
- 规则：表达动作的轨迹与对应数据卡片共用同一模型的显隐状态，流转开始时出现，结束后淡出；不能当背景装饰常驻，也不另设可能漂移的计时器。结构关系线与传输轨迹区别处理，不一刀切隐藏所有线。
- 验证：逐帧比较轨迹与数据卡的透明度；开场、整理确认、形成后及循环回起点均无残留。桌面／手机两条路径及减少动态、无脚本回退都需要检查。

## 不把受众标签直接做成页面结构

- 用户纠正：不要直接展示「员工视角／管理者视角」或轮播两篇受众说明。应通过一条流程，把双方关心的事自然结合，让价值从实际工作中被感受到。
- 规则：从日常工作及其记录、经验出发，经人整理确认后形成数字员工，再承接下一项任务并由人审阅。个人减负、团队方法积累、过程透明与交付质量嵌入这些节点，不另列管理者／员工卡片或切换入口。图中流转必须实际发生，不能只换文案，也不能直接以就绪员工开场、事后补回经验。
- 验证：去掉受众名称后，仍能指出工作怎样变轻、谁判断结果、方法怎样留下、下一项工作怎样受益；不能将手动整理与共享误画为自动学习。

## 官网用动画与架构解释，文字只提核心

- 用户纠正：区分视角不等于写两篇说明；动画与架构关系更容易记住，文字要简单、高效。
- 规则：先让画面展示谁参与、怎样交接、何时由人判断。每个关键节点只保留一句价值、必要角色和阶段标注，详细解释链接文档；添加图时删除被替代的长文，不在长文旁边堆装饰。复用已验证机制，但不能把隔离执行硬说成自动学习或组织效率提升。
- 验证：普通尺寸与手机先看图能否辨认主体和交接，再看几段真实动作。动画停下或加载失败时仍能理解核心；自动播放、鼠标停留时持续推进、减少动态与无脚本都要验证。

## 官网先说明人与组织的共同收益，再解释数字员工

- 用户纠正：官网要分管理者与员工视角，不能将平台放在员工的对立面。管理者关注人员效率与企业 AI-Native 程度；员工关注更有价值的工作，以及平台如何帮助完成工作。
- 规则：首屏与正文以辅助人的工作为共同主张，将组织协作、方法复用与个人减负、判断和创造自然融入同一工作流程，不直接按受众分栏或切换。数字员工是协作能力，不以替代人员、缩编或招聘替身作为默认卖点。可观测性解释为看清 AI 执行、核对结果与纠正经验，不自动扩张为人员监控或绩效评分。
- 验证：中英文首屏、视角区块和概念页均能回答“对管理者有什么价值、对员工有什么价值、怎样依据工作证据改进”。效率与成长不编造百分比，不把自动沉淀等同于自动变好；真实演示继续保留人的确认、纠正与验收职责。

## 先验证数字员工的业务组成与人的职责变化

- 用户再次纠正：日常工作应从人和大模型通过 Chat 做事开始，先沉淀 Skill、MCP，随后形成 Agent；Agent 加上 Skill、MCP 才组成数字员工。后续人指派任务，员工执行，人负责审批验收结果。
- 规则：Agent 与数字员工不能直接等同，Skill 与 MCP 不能缩成匿名经验薄片或外围标签；需要清楚地保留不同对象，并展示它们实际组合。人必须在早期参与 Chat、后期委派和审批验收，不能从画面消失，也不能由员工自行完成最终验收。MCP 表达可复用的工具接入能力，不声称生成协议本身。
- 验证：逐阶段指出“谁在做什么、哪些对象已形成、哪些尚未组成”，再观看中间交接动作；验收标记只能在人收到成果之后出现。阶段数量由业务链决定，不能为了沿用播放器四个按钮删掉关键过程。形体、接触、类型和构建通过只证明实现质量，不能证明业务模型正确。

## 员工要成为可辨认并亲自做事的主体

- 用户纠正：概念图只有身份卡和加工机器，无法看出数字员工，缺少具象化。
- 规则：员工身份标识不能代替可辨认的主体。以用户已确认的角色轮廓与持续身份建立主体，任务卡交接、工具调用和验收状态表达其工作，不再强制增加头身四肢或机械动作。后续任务始终归属同一角色，人的最终验收职责保持独立。
- 验证：先在实际页面的正常尺寸和 320／390 像素手机上检查，不读图注也能指出“哪一位是员工、它正在做什么”。再验证经验先于完整员工、雇用先于后续任务，以及来源与员工身份一直保留；不能用实体数、几何通过或增加名词标签替代视觉验收。

## 动画自动播放，鼠标悬停不暂停

- 当前约定（2026-10-18 最新反馈）：用户取消悬停暂停。所有动画继续自动播放、自动轮播，不显示播放、暂停、阶段或视角切换按钮；鼠标停在内容或空白处都不能停止演示。这取代同日早先的悬停暂停要求。
- 规则：删除悬停监听与相关提示，不只隐藏控件。保留键盘聚焦暂停、离屏／后台停止、减少动态静态展示和打开原图时暂停；鼠标点击和触摸不能留下粘滞暂停。
- 验证：对首页品牌、流程图、概念／架构图和原生产品演示，检查鼠标长时间停留时的真实时钟与画面推进，以及完整轮播；回归键盘、触摸、减少动态与原图检查。

## 产品截图需要展示操作过程

- 用户反馈：产品概念页有些动画未自动播放，希望直接基于产品图片实现动态效果。
- 规则：不能把静态截图算作动态演示；以真实界面的连续状态、实际操作位置和结果变化解释工作过程。播放交互统一遵循上面的自动轮播约定。
- 验证：检查真实画面变化、完整循环和截图放大，不只检查组件挂载。

## 产品机制插图要与实际页面配对

- 用户要求：产品概念、架构与使用文档结合 fusion-harness 的实际页面，并用 Anatomy 改善概念和架构的解释。
- 规则：先核对实际入口、操作和领域边界，再用各自可辨认的机械机制解释关系；真实截图继续承担操作对照，插图不冒充产品界面。
- 验证：自动演示到每个阶段并捕获静帧后，必须能看到该阶段已形成的关键对象。几何没有穿插、动作已经完成，不代表身份或成果没有被其他实体遮住；需要检查静帧、手机和放大细节。

## 开放中立不能画成品牌名单加通用流程台

- 用户否定：把模型与 Harness 变成图形上下两排名单，中心仍是无身份的工位与流程台，整体设计生硬。
- 规则：品牌应依附实际参与工作的 Agent，模型／Harness 选择应通过可替换部件和接入动作表达；先设计参与者、共同工作对象和实质交接，再考虑分类说明。移除占据主体的空底板和重复托盘，放大核心工作对象；不要仅靠罗列名称、流程大字及状态句解释协作。
- 细化：模型候选必须共用有承托且连接执行端的选择匣；当前模型名就近归属执行端，不能标在其他候选旁。品牌名放在稳定留白，亮度低于共同工作对象；手机通过画幅调整收紧顶部空白。
- 验证：静止画面先看出参与者围绕什么工作；播放能追踪同一份工作经过谁、发生了什么变化。视觉审查必须质疑构图与主次，不能用无溢出、类型及几何通过替代设计判断。

## 多 Agent 协作要体现开放中立

- 用户纠正：协作幕需表达任何模型、任何 Agent Harness 的开放选择，包含 Claude、Codex、Kimi、GLM、DeepSeek、Grok 等，而非只围绕 Claude 与 Codex。
- 规则：把模型、Harness 和执行职责分开表达；用分别接入的标准接口体现中立，工位按职责命名，避免品牌与职责绑定。示例品牌应等权展示并保留可扩展含义，名称使用 DeepSeek 等正式拼写。
- 验证：图中模型与 Harness 两层清楚可辨，接入发生在分工执行之前，后续共享同一交接和交付机制；完整静态图也能读出开放选择。不得用未验收的具体模型／Harness 配对冒充兼容矩阵。

## 数字员工先从工作记录与经验形成，再承接任务

- 用户再次纠正：首页应先有工作记录与经验，然后才沉淀出数字员工；不能以已存在的员工执行任务、事后留下方法来替代员工形成过程。
- 规则（员工培养图）：开场只展示人与模型的日常工作，随后实际出现记录与经验。人整理职责、方法、工具配置并确认方案后，才形成和配备员工；创建就绪或确认雇佣后才能委派下一项任务。经验分析不等于员工创建，不将整理确认误称为自动训练或自动学习。2026-10-18 信息架构重组后，完整培养图移至工作方式页；首页已有员工参与协作的概览不是培养过程，不能混用两种动画合同。
- 验证：开场员工和新任务必须不可见；记录与经验完整出现后才能整理方案，确认完成后才允许 Agent 出现，配备就绪后才能承接后续任务。保留来源记录直至人审阅交付；对纯模型的中间位置及实际浏览器六个阶段同时检查，不能只验证标题或最终静帧。

## 首屏文案、主视觉与主题标注共享布局

- 用户反馈：左文案、右动画和下方独立主题条各自成块，首屏布局混乱。
- 规则：主题标注应紧随对应的文案与行动入口；先组织共同网格和阅读顺序，再优化各块内部细节。主视觉中的图号、副标题和状态不能撑出另一组独立版式；保留必要说明，收紧重复层级与无意留白。
- 验证：在相同视口对比首屏截图，确认两栏整体对齐；双语三幕尺寸稳定，平板及手机的文案、主题标注与动画顺序清晰。

## 首页避免重复播放器层级

- 用户反馈：首页主题下方的计数、前后切换与播放控制造成多余占位，随后明确所有动画不需要控制按钮。
- 规则：主题名与阶段名仅作非交互标注，不再承担选择、暂停或重播；沿用上面的自动轮播约定，不同时堆放章节、计数和播放器工具栏。
- 验证：桌面和手机没有动画控制按钮，已清理旧控件的样式与手动播放分支；主题标注仍能让人辨认当前画面。

## 营销页的信息密度

- 用户反馈：整个网站文字过多，缺少架构图、流程图，首页需要动画图片与 slogan。
- 规则：营销页先明确一句核心表达，以图形承担架构和流程解释，长段技术说明按需展开；不把带编号的文字列表当作流程图。
- 验证：检查首屏是否有明确 slogan 与主视觉，架构是否表达边界和关系，流程是否展示方向；同时检查移动端阅读与减少动态效果模式。

## 品牌首屏与语言交互

- 用户纠正：三组小流程插画不足以表达期望的首页视觉，应参考全幅沉浸式主视觉，左侧集中 slogan 与 CTA。
- 规则：区分品牌主视觉和技术说明图；首屏承担品牌表达，流程/架构放后续区域。用户指定参考时优先对齐构图、比例、视觉重心。
- 语言控件采用图标触发的下拉选择，支持当前语言标识、键盘、Escape 回焦和外部点击关闭。
- 验证：用真实首屏截图对照参考，同时检查文案可读性与移动端裁切。

## 参考图不能替代产品设计

- 用户纠正：上一版沿用了参考图的流线主视觉，没有结合本项目设计动画。
- 修正规则：参考只用于理解信息层级和视觉质量；动画主题必须从产品独有机制推导。先列出每个图形/运动对应的领域事实，再实现画面。
- 本项目：冻结规格、单任务沙箱、Supervisor 调度、Artifact 交接与可审查变更是主视觉的依据；不使用无业务语义的流线背景。
- 验证：首屏无正文解释时，仍能看出输入、隔离执行和交付的方向；不把过程示意包装成实时任务或自动上线。

## 先预览视觉方向，再实现品牌动画

- 用户纠正：执行舱框图仍显陈旧，缺少现代、数字化和 AI native 感。
- 规则：产品语义准确不等于品牌视觉成立；首屏不直接放大技术框图。重大风格调整先提供多张高保真概念图比较，再依据选定方向实现。
- 当前任务只生成视觉预览，不继续修改网页实现。

## 动画插图必须对应章节

- 用户纠正：数字员工、专业协作、经验积累三幕插图不匹配。
- 规则：每幕先定义主体、动作与结果，再制作插图；不以替换相近背景加漂浮粒子代替叙事。保留统一身份符号，但构图与运动方向必须体现不同机制。
- 验证：分别截图与播放三幕，检查身份可识别、协作有共同成果、经验有证据与验证；键盘聚焦暂停时也必须有完整画面。

## 简约科技视觉与说明图的边界

- 用户纠正：头像、角色标签与流程线虽准确解释产品，但画面太死板，缺少科技、现代与简约感。
- 规则：已选择品牌视觉方向后，优化语义不能退回图标流程图。主视觉以空间、材质与运动表达机制，关键领域标识就近保留，长段解释放后续内容；一次画面仅保留一个视觉主题。
- 验证：分别以静态截图和动画检查形态与节奏；三幕构图须有区别，同时维持同一数字材质；视觉验收不能仅靠类型检查和无溢出测试。

## 主视觉必须出现可辨认的产品机制

- 用户纠正：抽象圆环、方体与分层颗粒仍未匹配主题；多 Agent 要体现 Claude/Codex，数字员工要体现 Agent、自动沉淀、RSI、Skill、Memory，经验积累要体现知识库。
- 规则：简约不等于删掉产品身份。先固定每幕必须被识别的真实对象与关系，再用少量具名元素、空间材质与运动设计画面；不再仅用图形轮廓或文案解释产品寓意。
- 验证：不读正文也能在主视觉中指出每幕的关键对象；暂停时仍有完整关系，运动体现分工、证据沉淀、知识检索复用。核对执行 Agent 与模型、私人 Memory 与知识库及 RSI 当前完成边界。

## 动画必须承担叙事，不能只装饰静态图

- 用户纠正：需要动画 logo，不能文字、数字和简单图像拼起来再加漂浮。
- 规则：每幕先规定起因、主体动作、结果与下一次使用，再制作连续分镜；图形本身通过绘制、接收、验证、构成、引用与复用表达主题。保留真实标识身份，标签仅辅助识别，不充当动画内容。
- 验证：查看 2 秒、6 秒、10 秒及完整视频，确认状态实质改变；三幕分别以“后续复用”“共同成果闭合”“带来源返回”收束，不能全是旋转、跑光点或透明度变化。鼠标停留期间也须播放完整短片。

## 先研究同类产品的实际宣传构图

- 用户纠正：Agent Swarm 的协作中枢、多角色网络和可见成果，才接近需要的宣传图效果；应调研好的对标产品再设计。
- 规则：收到视觉参考后，重新以参考中的主体、关系和视觉层次定义构图。实际查看官方宣传图，记录可迁移的设计方法，再结合产品机制制作原创动画。不能用商标拼接或抽象几何替代真实工作网络。
- 验证：暂停画面能指出“谁在工作、如何协作、产生什么”，完整播放能看见任务流和成果形成；对标结论区分实际观察与设计推论。

## 视觉优化需要覆盖整页布局

- 用户纠正：主题图清楚之后，仍需进一步现代化与科技感，同时关注页面布局。
- 规则：主视觉、导航、图文比例、内容区节奏和页尾应作为一页整体设计；不要只调整插图细节就宣称整页优化。保留明确产品机制，用比例、层次和空间关系提升表现。
- 验证：实看桌面、平板、手机的首屏和全页，特别检查中间尺寸的插图挤压、移动导航多占一行和重复三等列布局。

## 技能不能替代已有产品的视觉判断

- 用户纠正：使用 high-end-visual-design 后，效果“还不如之前”。
- 本轮变化：将原有简约技术视觉大量包进圆角面板，叠加浮岛导航、字体更换和留白，改变了整站已有的比例与节奏。
- 规则：技能中的圆角、嵌套外壳、导航和动效是可评估的技法，不作为整站换样式的目标。先保留已有视觉成果，只针对明确不足做小范围改善；风格变化必须先与原版同视口对比，不凭规范检查通过判断设计更好。
- 验证：比较首屏主体、整页节奏与手机阅读；当用户明确认为退步，先恢复已验证基线，再讨论后续具体改善。
- 用户进一步明确：产品为 ToB 的 AI Native / AI Infra，需重点思考每个主题的动画，现代、科技、数字、简约、时尚，可使用多色彩。后续先设计主题主体与动作，以克制的多色和材质表达工作机制，不将消费产品的圆角面板风格套在整站上。
- 用户认可三幕主体与动作，但指出色彩样式偏卡通，并给出 APIGO 开源站参考。规则：多色彩不等于大面积糖果色；避免把证据、方法和索引做成厚积木，用中性色承载主体、少量色彩标记工作，减少厚侧边、弹跳和高亮塑料感。验证：对照上一版静态与完整播放，同时检查色彩占比、材质、边缘和动作，而不是只降低饱和度。

## 域名解析正确与 HTTPS 就绪必须分别验证

- 用户反馈：按 DNS 与 GitHub 自定义域名步骤设置后仍无法访问。
- 规则：不能仅凭 DNS 记录正确推断站点可用；分别检查公共解析、GitHub 域名健康状态、实际响应服务器与 TLS 证书。普通请求仍命中旧服务时，使用指定正确边缘地址的请求区分本地或代理缓存与托管服务的问题；不把强制地址检查成功表述为普通用户访问已恢复。
- 验证：HTTPS 请求必须启用严格证书校验并返回真实页面，HTTP 必须正确跳转；证书仍处于申请状态时明确报告未完成。按官方建议重启证书申请后保持域名和 DNS 稳定，避免重复重启延长等待。
