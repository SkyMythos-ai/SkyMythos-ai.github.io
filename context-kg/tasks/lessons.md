# 官网转化与产品演示边界

- 企业产品官网的“体验”不能默认解释为自助试用。先确认销售转化方式；用户明确 POC 联系后，主要 CTA 应引导填写需求并联系团队。产品场景展示用于解释能力，不应提供模拟创建任务来替代 POC。
- 联系表单必须区分资料已填写、已准备邮件与接收方已确认收到；未接通实际接收通道时不得显示提交成功。

- 首屏说明应尽量压缩为一句清楚的价值表达，让正文自然换行；避免强制拆成多行，并避免同时堆放重复的侧边推广。用户要求动态产品展示时，应呈现可理解的工作推进过程，而不是只做入场淡入或静态完成态。
- 当首页产品原型承担主要展示时，应独立于正文阅读宽度进行布局，但“铺满下方”不能默认解释为左右贴边；保留随视口增长的留白与最大宽度，同时检查报告是否产生不必要的内部滚动，而不只检查页面有无横向溢出。

- 面向持续维护的产品文档，应采用成熟文档框架及独立Markdown/MDX内容源，复用导航、搜索、目录与代码展示能力；不能把手写文章页包装成完整文档系统。
- 文档接入框架后仍需核对当前界面的入口、字段、生效方式和失败状态，给出具体步骤、验收与排障；不能仅扩写产品定位。旧文档与当前实现冲突时，以当前代码和真实界面契约为准。

- 首屏原型顶部保持产品导航，按用户明确要求移除额外的演示说明与播放控件；删除这些辅助区域时，保留自动演示和减少动态偏好等既有行为。
- 官网导航顺序按用户偏好：价格在文档前，桌面与手机同步。
- 价格页的技术审计通过不代表信息密度合适。用户给出稀疏卡片参考后，应优先呈现方案、报价方式与联系入口；费用长表、流程说明和大段FAQ不应挤占价格决策页面。
