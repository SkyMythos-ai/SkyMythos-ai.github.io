# 官网页面职责与叙事

2026-10-18：用户指出产品、概念、架构混乱，指定产品 PPT 为参考，并在阅读方案后授权实施。当前三页已按下述职责重组；保留深石墨主题、已确认角色与现有路由。实施验证记录见[任务 Review](../tasks/todo.md)。本文取代原待确认提案。

PPT 提供叙事与表述边界，不单独证明产品已交付。三种工作入口、个人环境与任务隔离、知识实时授权的边界另与 `fusion-harness` 已提交版本 `ea6c4b51e` 的 `context-kg/business/product-strategy-and-domain-model.md` 对照；该文档仍包含历史与目标段落，不能将全文当作当前生产能力验收。

## 采用的产品主线

承认现有 Agent 的执行能力 → 企业需要组织跨人、跨项目的工作 → 用一次交付说明产品 → 留下可复用的方法 → 解释企业如何掌控。

PPT 页码按实际播放顺序，不按 slide 文件编号：第 2–5 页讨论组织成本与自建／采购；第 6–8 页建立产品定位与工作主线；第 9–12 页用订单导出贯穿目标、执行、判断与结果；第 13–15 页讲流程、员工与经验复用；第 16–18 页讲治理、接入与部署；第 19–20 页讲真实工作验证。第 21–25 页的入口、资产、研发生命周期、IM 与对象定义属于渐进披露，不整套搬到首页。

## 唯一页面职责

| 导航 | 路由 | 核心问题 | 不再承担 |
| --- | --- | --- | --- |
| 产品 | `/` | 它是什么，为什么需要它？ | 配置教程、术语大全、完整研发状态机 |
| 工作方式 | `/concept` | 一项工作怎样被组织、交付并复用？ | 重复首页宣言、底层组件清单 |
| 企业架构 | `/architecture` | 如何接入已有系统，谁控制资源与执行？ | 完整任务操作教程、重复培养动画 |
| 使用文档 | `/docs/...` | 怎么配置、操作、排查与部署？ | 无证据的商业承诺 |

导航、页脚、标题、描述、面包屑与结构化产品描述同步；保留路由避免既有入口失效。未确认定价不写入零价格 Offer。

## 产品首页

- 固定定位「企业自己的 AI 工作体系」，不再随三幕轮播切换产品定义。
- `WorkOverview` 使用已有协作者解释同一份工作的委派、执行、证据返回与人工验收，不表示新员工形成过程。
- 简短解释已有 Agent 之后的组织问题，不把其他产品描述成没有执行、安全、自动化或扩展能力。
- 目标 → 工作方式 → 有依据的交付 → 有效方法留下，展示工作概览；完整订单示例在工作方式页。
- 工作记录与经验经人整理确认后，成为方法或数字员工，用于后续工作。首页只保留来源与复用关系，不重复完整培养演示。
- 简述已有模型、运行时、Git 与工具接入；以真实任务评估交付周期、人工投入、验收质量与单次成本。
- 原 Agent 表单、MCP 协议、首次使用截图、七步研发 Pipeline 与能力清单不再挂载首页，相关操作仍由文档承接。

## 工作方式

- 三类入口是选择关系：对话协作、研发任务、周期／事件自动化，不是三个串行步骤。
- 普通对话不隐式创建研发 Task；Automation Run 保留独立身份，不能泛化为研发 Task。
- 订单导出使用 PPT 原图，按目标 → 方案确认 → 执行 → 核对交付的顺序自动演示。审批是该示例配置的策略，不宣称所有工作每步都需要确认。
- 图片保持原样，焦点随桌面／手机调整，支持原图检查。不同状态 ID、测试数与 PR 编号均为固定演示数据，不能当同一真实后端运行或客户业绩。
- 完整 `HomeWorkflowFigure` 仅在此页出现：日常工作 → 记录经验 → 整理确认 → 形成员工 → 承接新任务 → 人审阅交付。组件保留历史命名，职责以本页为准。
- 培养不是每次工作的前置条件；也可雇用已发布角色。角色定义职责与方法，员工保留长期身份与独立经验；共享不自动复制私人历史或凭据。
- 企业知识、员工经验、Skill、Flow 用简短用途分类说明，详细配置和定义链接现有文档，不再并列多套功能演示。

## 企业架构

- 一张逻辑总图先展示工作入口、工作组织、执行环境、工作资产与外部接入；身份、资源授权、凭据与观测作为跨层治理职责。
- 个人云环境与研发任务 Sandbox 分开，Agent 运行时与模型分开，不把一任务一 Sandbox 泛化到每个对话。
- 边界说明围绕资源访问、凭据使用、工作运行位置与证据追溯。控制面、运行器和环境 Provider 保留不同事实权威。
- AWS 是参考拓扑：客户环境内控制面与执行环境，数据库、对象存储、遥测等服务按实际方案选择；模型、Git、IM、外部工具的数据流另行配置和验收。
- 私有部署不等于零外发；不把部署位置当合规证明，不承诺任意模型／运行时互换或无限恢复。
- 完整研发执行机制不作为架构页开场，操作和诊断链接文档。

## 图形与交互合同

- 首页讲价值与协作概览，工作方式页讲动作与结果，架构页讲组成与边界；完整培养图只保留一个营销页归属。
- 自动播放、悬停不停，不显示播放／暂停或阶段切换按钮。键盘聚焦、打开原图、离屏、后台与减少动态按各播放器合同处理。
- 表示传输的轨迹与数据卡共用模型显隐，流转外不常驻；架构关系线不伪装正在运行的数据流。
- 无脚本保留语义文本、静态图、案例步骤和原图链接；少量动画不承担唯一的信息入口。
- 跨语言使用原生链接完整加载导出 HTML，显式携带 basePath，保留路径、查询与锚点。本轮实际发现跨 locale 的共享 layout RSC 分片请求 404，不能仅用静态 URL 可达代替真实导航检查。

## 验证入口

- `node scripts/check-product-story.cjs`：601 个首页协作模型位置，检查委派、证据、返回、人工验收的先后。
- `node scripts/check-home-workflow.cjs`：1001 个员工培养模型位置，组件迁移后仍保持记录经验与人工确认先于员工、新任务晚于就绪。
- `npm run typecheck`、`npm run build`：类型与 57 项静态导出。
- 浏览器检查三页 × 中英文 × 1440 / 1024 / 768 / 390 / 320，实际导航与锚点、自动轮播、图片解码、键盘、原图、减少动态与无脚本。通过记录只写入任务 Review，不把新增测试代码本身当验证通过。
